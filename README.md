# LiveClipper

LiveClipper 是面向 **Windows 11 x64** 的 B 站直播录制与剪辑工具。你可以在直播时只缓存最近一段内容，遇到值得保留的场面再保存高光；下播后，把素材转成带时间码的字幕，在时间线上选段、精剪并导出视频。不需要先配置大模型，也能录制和手动剪辑。

**[下载 LiveClipper v1.3.1（Windows 11 x64）](https://github.com/davidd4242/LiveClipper-Releases/releases/tag/v1.3.1)** · [从源码构建](docs/BUILD.zh-CN.md) · [报告问题](https://github.com/davidd4242/LiveClipper-Source/issues)

## 安装：我要用软件，不是编译源码

1. 打开上面的发行页，在 **Assets** 中下载 `LiveClipperSetup.exe`。如果需要安装说明和第三方组件清单一起打包，选 `LiveClipper-win-x64.zip`；ZIP 里也是安装器，**不是免安装版**。GitHub 自动生成的 **Source code (zip)** 也不是程序。
2. 发行页为 EXE 和 ZIP 分别提供了 SHA-256。用 PowerShell 核对你下载的那一个，例如 `Get-FileHash .\LiveClipperSetup.exe -Algorithm SHA256`。v1.3.1 安装器未作 Authenticode 签名，哈希不能替代签名；若来源或校验值不符，请勿运行，不要关闭系统防护。
3. 中国大陆的百度网盘手动备用入口也在发行页。若首次完全连不上 GitHub，软件不能自行取得尚未读取的备用地址，可直接使用事先保存的分享链接。
4. 按安装向导准备运行环境。安装包自带 .NET 桌面运行时，但仍需要 WebView2，缺少的组件可能要联网下载。已有工程请先备份。安装后可在「设置 → 关于」手动检查更新；程序不会自动运行下载的安装器。[安装、更新与卸载说明](installer/安装与卸载.md)

## 实战：从一个直播间到一条成片

先决定要保留什么：

| 目标 | 在直播控制台怎么选 |
| --- | --- |
| 只留精彩片段 | 开启「高光临时缓存」。缓存会过期，要长期保留就生成高光。 |
| 保留完整直播 | 开启「保留整场自动录播」，先确认录制目录和可用空间。 |
| 只看，不写媒体文件 | 关闭临时缓存和整场录制，选「仅在线预览」。没有缓存，便不能回取刚才的直播画面。 |

1. **添加房间并开始监控。** 从侧栏进「直播」，先在「录制目录」保存位置，再输入房间号、UID 或 B 站链接。点「识别直播间」，核对主播和房间。若只留高光，点「开始监控并缓存高光」；光看到直播画面，不代表已经写入缓存。
2. **让软件留下一条高光。** 在「自动切片」打开开关，确认状态为「已启用 · 等待热度触发」。自动切片依赖可用缓存和弹幕热度，不是按画面或解说识别精彩瞬间。暖机未完成、弹幕太少或显示「弹幕未授权」时，可能没有自动高光；只要已有完整缓存分片，就可以主动点「手动高光录制」。等状态变成「已保存」，再选片。
3. **回看并选片。** 展开「最近自动切片」的已保存条目，点「下载 MP4」并用本地播放器回看。1.3.1 不会自动弹出高光回放；直播预览仍是实时画面。确定保留哪条后，回「工作台 → 最近切片」，按标题和时间找到该条目，点进去打开剪辑工程。
4. **转写，先校对字幕。** 在编辑器打开「转写字幕 → 生成字幕」。首次可能需要准备转写模型。完成后在「编辑字幕」校对文字和源片时间，再点「保存字幕并载入工程」。转写是把原声变成字幕，并非翻译；要让字幕出现在工程里，还需「放置字幕到时间线」。
5. **分析并选事件。** 在「AI分析」里点「开始 AI 分析」；不用模型时可手动选「规则提取候选」。分析只给候选，不会自动改时间线。进入「选择事件」，按标题和源片时间回听，只勾要留的片段。首次点「放置选中事件」会替换当前主源的原始整段，保留手工片段及其他源；之后勾选变化会同步对应事件片段。已有剪辑先保存或备份。
6. **粗剪、精剪、导出。** 打开「AI粗剪 → 语义粗剪 → 生成粗剪区间」，先核对区间和理由。粗剪依据的是主源，**并不只处理上一步勾选的事件**；只有点「确认并追加到工程末尾」才会改时间线，且是追加，不是覆盖。追加后检查是否有重复话句或重叠内容，手动调整剪点，试听接缝，校对字幕，保存到显示「已保存」。最后选「导出 → 导出视频」，用 H.264 / MP4；要把字幕写进画面则选「烧录字幕（仅本次导出）」。出现「渲染完成」后，点「在文件夹中显示」，用播放器复核成片。需要单独字幕时可导出 SRT。

### 转写模型和 AI 服务是两回事

语音转写使用本地语音模型，可以在设置的「转写模型（ASR）准备」中检查。模型分析另在「设置 → AI 连接」配置，例如本机 Ollama，或兼容 API 的 Endpoint、Model 和 API Key。测试连接能列出模型，不代表实际推理一定成功。录制、手动剪辑和「规则提取候选」不需要聊天模型。选择在线服务前，先确认你有权发送相关字幕或素材，别把密钥写进日志、截图或 Issue。

## 从源码构建

此仓库是基于 **v1.3.1 发行构建输入**整理的源码版，**不是已发布安装包的逐字节可重建副本**。平台说明只覆盖本版的 Windows 11 x64 发行目标，不代表其他系统或架构已验证。

| 路径 | 内容 |
| --- | --- |
| [src/](src/) | .NET 桌面外壳、应用接口、工程模型、直播采集与剪辑服务 |
| [web/](web/) | React / TypeScript 工作台：直播监控、设置与编辑器界面 |
| [ai-worker/](ai-worker/) | Python 转写、音频及草稿处理工作器与依赖清单 |
| [installer/](installer/) | Windows 安装器、发行组件清单和第三方通知 |
| [tests/](tests/) | .NET 测试源码 |
| [docs/](docs/) | 构建步骤、第三方来源及编辑器运行文件校验清单 |

Windows 开发环境使用 **.NET SDK 10.0.404**、PowerShell，以及符合 Vite 锁文件要求的 Node.js（20.x 从 20.19 起，或 22.12 及以上）。先按[完整构建说明](docs/BUILD.zh-CN.md)从官方包恢复指定的 **hls.js 1.5.20** 并核对哈希；需要完整编辑器时，再按同一文档恢复配套运行文件。完成相应准备后，在仓库根目录执行：

```powershell
Push-Location web
npm ci
npm run build
Pop-Location
dotnet restore ./src/LiveClipper.Desktop/LiveClipper.Desktop.csproj --locked-mode
dotnet build ./src/LiveClipper.Desktop/LiveClipper.Desktop.csproj -c Release --no-restore
```

以上命令按项目文件和锁文件整理；公开源码树未单独完成端到端构建验证。完整的依赖恢复、WebView2 和安装器说明见[构建文档](docs/BUILD.zh-CN.md)。

**源码版与发行版的差异：** 本仓没有捆绑两组含上游衍生 JavaScript 和嵌入式编解码器的编辑器运行文件。若已有合法取得的官方 v1.3.1 安装，可以按[154 项路径与 SHA-256](docs/editor-runtime-files.csv)在本机逐项恢复；未恢复时不要假设高级编辑器可完整使用。公开源码版还禁用了读取外部浏览器已有登录状态的功能，并以中性图形替换原品牌标志和六枚旧图标。这些调整不会改变已分发的 v1.3.1 安装包。
